# 我的理财看板

个人理财数据看板（占位骨架版），部署于 GitHub Pages：
<https://se-daming.github.io/finance/>

## 功能

- **大盘指数**：上证指数、深证成指、沪深300 实时行情 + 上证近 30 个交易日迷你走势
- **外汇 · 贵金属**：美元人民币、欧元美元、COMEX 黄金、COMEX 白银
- **自选基金 / ETF / 股票**：输入 6 位场内代码添加（如 `161725`、`510300`、`600519`），保存在浏览器 localStorage，可随时移除
- **基金持仓**：读 [data/holdings.md](data/holdings.md) 里的表格，改表即改数据。表里逐只写基金和它的**类别**，看板按类别自动汇总。自上而下是：顶部总览（持有金额 / 累计成本 / 累计收益 / 收益率 / 每日定投）、类别卡片、仓位分布条、收益贡献条形图、定投节奏、基金区间收益、按类别分组带小计的明细表
- **基金区间收益**：每只基金的 1 日 / 1 周 / 1 月 / 3 月 / 6 月 / 1 年收益率对比表，红涨绿跌
- **持仓推算**：`data/holdings.md` 里的市值是快照，页面显示的是以「快照日期」为锚、按每日定投计划**逐个 A 股交易日**滚到今天的推算值，所以每过一个交易日就往前推一期定投，净值在波动时数字也跟着变。跑偏了粘贴一份新快照重新锚定
- **同步净值**按钮：点一下，浏览器当场去天天基金拉每只基金的最新净值，把上面那两块重算一遍，结果存在浏览器本地，之后打开页面直接用它。不点就用仓库里预生成的那份
- 占位模块：收支记录（待接入个人记账数据）

## 技术

纯 HTML / CSS / JavaScript，零依赖、无构建步骤。数据来自腾讯财经和天天基金的公开接口，
全部通过 `<script>` 注入获取（免跨域），行情每 60 秒自动刷新。

页面本身零依赖、不需要构建、也不需要服务端。「基金区间收益」和「持仓推算」有两份实现，
算的是同一件事：

- **页面**：点「同步净值」按钮时，用 `<script>` 注入天天基金的净值文件，当场算
- **`data/returns.json`**：推送前跑 `node tools/update-returns.mjs` 预生成，页面首屏直接读它

两份共用 [js/nav-math.js](js/nav-math.js) 里的同一套算法（浏览器 `<script>` 直接加载，
Node 用 `require` 读），所以算出来的数一定一样——同一套金额规则写两遍，迟早会算出不一样的结果。

所有资源使用相对路径引用，可部署在任意子路径下。

## 持仓数据怎么改

持仓不写死在代码里，全部来自 [data/holdings.md](data/holdings.md) 里的一张表格：

1. 编辑 `data/holdings.md` 的表格
2. 跑 `node tools/update-returns.mjs` 刷新仓库里那份净值数据（没网就跳过，页面会少一个区块，不会报错）
3. 推送，或本地刷新页面

只想知道最新净值、没改表的话，不用跑脚本：打开页面点一下「同步净值」按钮就行。

从基金 App 抄了新数字时，别忘了把表上方那行 `快照日期：YYYY-MM-DD` 改成你抄的那一天——
不改的话推算会从旧锚点继续往前滚，把已经算进去的定投重复累加一次。

派生列和汇总行由看板计算，**不要写进表格**：

- **成本** = 持有金额 − 持有收益
- **持有收益** = 持有金额 × 收益率 ÷ (1 + 收益率)——只填了「持仓收益率」、没填「持有收益」的行这样反推
- **收益率** = 持有收益 ÷ 成本
- 明细表末尾的**类别小计 / 总计合计**行

规则：

- 看板会跳过文档里的说明表，自动认**表头含「类别 / 基金名称 / 持有金额 / 持有收益 / 每日定投金额 / 投入本金」之一的那张表**，所以文档开头可以随便放说明表格
- 列可以增删、可以调换顺序，按**表头名字**识别（「持有收益」「类别」「持有金额」「每日定投金额」「投入本金」有特殊作用）
- 「持有收益」列自动上色：正数红、负数绿
- 「持有收益」和「持仓收益率」**二选一**，同一行只填一个。基金 App 上通常直接给收益率，那就填「持仓收益率」，看板自己反推金额；两个都填以「持有收益」为准
- 「代码」填 6 位基金代码。**区间收益那块只认有代码的行**，留 `—` 的基金不会出现在里面。代码填错了不会报错，只会静静取到别的基金的净值——拿不准就去 App 里看那只基金的代码。**每行悬停会显示接口返回的基金全名**，名字对不上就是代码填错了
- 「累计定投」是这只基金到目前已定投进去的累计金额。只用于展示：明细表里有这一列，类别卡片上也会按类别合计
- 「类别」是汇总的键：类别卡片、仓位分布、收益贡献、定投节奏都按它分组，明细表也按它分组加小计。**同一类别的行要连在一起写**，换类别就开一个新分组
- 「投入本金」是可选列，**只在明细表之外起作用**：一次性买入的品种往往只知道本金和盈亏，那就只填本金 + 收益、持有金额留 `—`，看板按 `市值 = 本金 + 收益` 推算。推算出来的市值在明细表里用灰色虚线下划线标出，鼠标悬停有说明
- 顶部汇总只累加**算得出市值**的行；既没填市值又没填本金的行会在顶部单独提示
- **纯定投计划行**：只填「每日定投金额」，金额和收益都留 `—`，会被当成定投计划——只进「每日定投」合计，不进市值、不报「未计入总额」。适合「一类基金合并定投、摊不到单只」的情况（表里的「其他纳斯达克定投」「其他标普500定投」就是）
- 「每日定投金额」写成 `50 元/天` 才会被计入每日定投合计；「定投节奏」里每月 / 每年按 21、250 个交易日估算
- 表格上方单独一行写 `快照日期：2026-09-13`（**整行只有这个，别在别处再写一遍**），说明表里的市值是这天从 App 抄的，推算持仓以它为锚。没这一行就不推算，页面直接显示表里手写的数字
- 没有数值的格填 `—`，不要留空；金额直接写数字，别带千分位逗号

> 根目录的 `.nojekyll` 是必需的：GitHub Pages 默认用 Jekyll 构建，会把 `.md` 编译成 `.html`，那样前端就取不到原始表格了。

## 净值相关的数据怎么更新

两种方式，算出来的数一样：

- **点页面上的「同步净值」按钮**：浏览器当场拉、当场算，结果存 localStorage，下次打开直接用。
  首次要下约 4 MB（二十多只基金整包，约 3.8 MB 未压缩），之后走浏览器缓存。表改了（比如换了
  新快照）缓存自动作废。适合「我就想看看今天最新净值」
- **跑脚本**：`node tools/update-returns.mjs` 写进 `data/returns.json`（二十多只也就几 KB），
  跟着代码一起部署。适合「改完表要推上去，让首屏打开就有得看」

```bash
node tools/update-returns.mjs
```

脚本读 `data/holdings.md` 里所有有代码的基金，逐只去天天基金拉净值走势。一件事产出两块数据：

**区间收益**是 1 日 / 1 周 / 1 月 / 3 月 / 6 月 / 1 年 的收益率。按官方**日涨跌幅**
逐日复利算的，不是拿首尾净值相除——后者遇到分红会把净值砸下去，算出假的暴跌。

长假之后「1周」可能和「1日」相同：那 7 天里只公布了一期净值，复利只有那一天的涨跌。
不是算错，也不是取数错位——每行悬停能看到各区间实际是从哪天开始算的。

**推算持仓**是以表上方的「快照日期」为锚，把市值滚到今天：

- 锚点净值 = 快照日期当天（或之前最近一天）的净值；快照市值 ÷ 锚点净值 = 快照那天的份额
- **快照日期之后**每过一个 **A 股交易日**，就按「每日定投金额」买进 `金额 ÷ 当日净值` 份，成本同步累加
- 推算市值 = 最终份额 × 最新净值

界是**快照日期**，不是锚点净值日：快照里的份额和成本已经是截至快照日期的数，只该补它之后的期数。
QDII 净值普遍晚一天，快照日期是周五时锚点净值日还停在周四，拿锚点净值日当界会把那个周五
重复补一期——钱确实扣了（App 的总成本里有），推算再加一次，成本和市值就一起虚高。

不能只拿「快照市值 × 区间涨幅」：那等于假设新投的钱期初就到位了，而定投是一天天买进去的，
越晚买的钱吃到的涨幅越少。没填「每日定投金额」的行就只随净值走。

**为什么按交易日、不按净值日推进**：钱是按交易日扣的，净值却常常晚一步才公布——QDII 要等
美股收盘，普遍比 A 股晚一天。按净值日推进的话，今天投进去的钱得等明天净值出来才认，
页面上的数字就一整天不动。所以当天净值还没公布的，用**最近的已知净值**当买入价先估一个，
等真净值出来，份额会从锚点整个重算，估算自动被纠正——不做增量累加，就不会错一次再也纠不回来。

交易日历取自上证指数的日K日期（腾讯接口，页面和脚本各拉一次，40 个交易日够用）。
用真实日历而不是「周一到周五」：节假日休市那天没有定投，按工作日算会永远多算、且不会自我修正。
两边都拿不到日历时退回只用各基金自己的净值日，少算的只是最新这一天，不会算错。

**误差是存在的**：实际扣款未必每个交易日都成功（QDII 有额度限制，美股节假日和 A 股也不同步），
所以估算值会慢慢偏离真实持仓，定期从 App 复制一份新数字覆盖表格、并改掉「快照日期」重新锚定即可。

跑完终端会打两张表，顺便能肉眼核对——同类基金的区间收益应该很接近，差太远说明代码填错了；
推算那张会列出「快照 → 推算」的差额，好判断漂移了多少。

两者都不是实时行情：页面那份是**点按钮那一刻**的，`returns.json` 那份是**跑脚本那一刻**的，
表头会写明净值截至哪天。

**为什么二十多只基金不自动刷？** 每只整包 100~550 KB，一次全拉大约 4 MB。放进页面自动跑
就是每次打开白下 4 MB；只放到推送前跑，页面上的数字又冻在上一版。所以做成按钮：
数据新鲜度归你决定，代价也就一次点击。

GitHub Actions 定时任务试过，撤了——用 `GITHUB_TOKEN` 推的提交**不会触发**其他工作流，
包括 `pages-build-deployment`，所以那个任务能改仓库里的 JSON，却永远刷新不了线上页面。
要让它生效得把 Pages 的构建源改成「GitHub Actions」或者配一个 PAT，都不如一个按钮干净。

## 数据接口说明

| 用途 | 接口 | 谁在用 |
| --- | --- | --- |
| 实时行情 | `https://qt.gtimg.cn/q=sh000001,sz399001,whUSDCNY,hf_GC` | 页面 |
| 日 K 收盘价 | `https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?_callback=cb&param=sh000001,day,,,30,qfq` | 页面（迷你走势图） |
| 交易日历 | 同上（取每行的日期字段，即上证指数的交易日） | 页面、`tools/update-returns.mjs`（推算持仓按它步进） |
| 场外基金净值 | `https://qt.gtimg.cn/q=jj160213` | 页面（只用来查代码，不取历史） |
| 基金净值走势 | `https://fund.eastmoney.com/pingzhongdata/160213.js` | 页面（同步净值按钮）、`tools/update-returns.mjs` |
| 基金代码搜索 | `https://fundsuggest.eastmoney.com/FundSearch/api/FundSearchAPI.ashx?m=1&key=<name>` | 手工查代码用 |

腾讯的场外基金接口（`jj` 前缀）只给最新净值，`day` 数组是空的，取不到历史——
所以区间收益只能走天天基金。

代码前缀：`sh` 沪市、`sz` 深市、`wh` 外汇、`hf_` 外盘期货（COMEX）。
实时行情返回 GBK 编码的 JS 变量（`v_sh000001="..."`），注入 `<script>` 时需指定 `charset="GBK"`；
字段以 `~` 分隔，股票/指数取 `[1]名称 [3]最新价 [32]涨跌幅`。

行情接口为公开接口，仅供个人参考，不构成投资建议。
